# project-mobile

The React Native (Expo) client for Ben. Day-to-day development needs none of the Android
toolchain below — `npm start` and Expo Go cover it.

## Branding assets

`assets/` is generated from the `BenLogo` geometry in
[`src/layout/components/icons/ben-logo.tsx`](./src/layout/components/icons/ben-logo.tsx) —
the three circles in `#121213` on the `#f9f9f9` surface. Run `npm run icons` to regenerate
(it also runs before `start` and `android`). The script writes PNGs directly through
`node:zlib`, so there is no image dependency to install.

| File | Used by |
| --- | --- |
| `icon.png` | base app icon (`expo.icon`) |
| `adaptive-icon-foreground.png` / `adaptive-icon-monochrome.png` | Android adaptive + themed icon |
| `splash-icon.png` | `expo-splash-screen` |
| `notification-icon.png` | `expo-notifications` status-bar icon for reminders |
| `favicon.png` | web |

Keep the generated files in version control. To change the mark, edit the geometry constants in
[`scripts/generate-icons.mjs`](./scripts/generate-icons.mjs) so they stay in lockstep with
`ben-logo.tsx`, then re-run the script.

## Android release APK

`android/` is generated by `expo prebuild` and gitignored, so the build is reproducible from a
clean checkout.

```bash
source scripts/android-env.sh   # once per shell: JAVA_HOME + ANDROID_HOME
npm run apk
```

That regenerates the icons, prebuilds, and runs `assembleRelease -PreactNativeArchitectures=arm64-v8a`,
which limits the build to one ABI: ~51 MB instead of the universal APK, and covers every current
phone. Drop the flag (`cd android && ./gradlew assembleRelease`) for the universal one. Output lands
in `android/app/build/outputs/apk/release/app-release.apk`. First build takes ~10 min; later ones are
much faster thanks to the Gradle cache.

The toolchain is JDK 17 under `~/.local/tools` and the Android SDK under `~/Android/Sdk`;
`scripts/android-env.sh` only exports the paths, it does not install them.

### API endpoint

The native client has no origin to derive the API from, so the backend URL travels through
`app.config.ts` → `expo-constants`. `.env.production` (gitignored) points `BACKEND_URL` at
`https://ben.df07.site`, and `expo-constants` embeds the resolved config during the Gradle build —
which is why the build runs with `NODE_ENV=production`. To confirm what a built APK will talk to:

```bash
find android/app/build/intermediates/assets/release -name app.config | head -1 | xargs cat
```

`http://ben.df07.site` answers with a 308 to HTTPS, and release builds block cleartext traffic, so
the URL must stay on `https://`.

### Signing

The Expo template signs release builds with the *debug* keystore, which cannot be distributed.
[`plugins/with-release-signing.js`](./plugins/with-release-signing.js) rewrites that on every
prebuild to read `credentials/keystore.properties` (gitignored, along with the keystore itself).
Without that directory the build falls back to debug signing, so `assembleDebug` still works on a
fresh clone but release APKs need the key.

Native Google Sign-In matches the signing certificate against the Android OAuth client registered
in the Firebase project `test-ben-1e234`. The release keystore's SHA-1 must be listed there, or
login fails with `DEVELOPER_ERROR`:

```bash
source scripts/android-env.sh
keytool -list -v -keystore credentials/ben-release.keystore -alias ben-release | grep SHA1
```

**Back up `credentials/` off-machine.** Losing it means the app can never be updated under the same
identity — Android rejects an update signed with a different key, and the package name
`com.benprototype.app` would have to be abandoned.
