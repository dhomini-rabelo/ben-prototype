# r0-mobile: lembrete criado no chat abre a tela de lembretes

Raiz mobile: `packages/infra/mobile/ben` (abrev. `ben/`), galeria: `packages/infra/mobile/design` (abrev. `design/`).

## 1. Como o chat renderiza o lembrete criado
- Renderização: `ben/src/pages/chat/components/chat-history/chat-history-item.tsx:50-89`. `capture = message.metadata?.capture`; se existe, monta `CaptureCard.Root kind={capture.kind}` com `Icon`, `Body > Title(capture.title) + Meta(capture.meta)` e `CaptureCard.Action` (linhas 76-89).
- **O card de lembrete NÃO é clicável.** `CaptureCardRoot` é um `View` puro (`capture-card/capture-card-root.tsx:57-71`), sem Pressable/onPress. O único toque no card é o `CaptureCard.Action`, e ele só renderiza para `kind === 'task'` (`capture-card-action-button.tsx:29-31`: `if (kind !== 'task' || state === 'error') return null`). Para reminder/note o botão some, então nada acontece ao tocar.
- Toque na bolha de texto do Ben (não no card): `MessageTracePressable` (`chat-history/message-trace-pressable.tsx`) abre o menu de ações/trace por long press (haptics + `useMessageTraceStore.openActions`). Não envolve o card, que fica fora dele (card é irmão da bolha, linhas 58-89).
- O `onAction` hoje faz `router.push(ROUTES.taskWorkspace(capture.itemId))` (linha 86): só faz sentido para task.
- Dados do card: `MessageCapture` em `ben/src/api/models/message.ts:5-10` = `{ kind: 'note'|'reminder'|'task', itemId, title, meta?: string|null }`. **`itemId` é o id do lembrete** (server: `domain/chat/src/application/use-cases/captures/persist-captures.ts:166-173` `toReminderView` -> `{ kind:'reminder', itemId: reminder.id, title, meta: reminder.props.remindAt }`). Tipo servidor: `packages/domain/chat/src/application/types/capture-view.ts`.
- **O card não tem recorrência nem tipo (alarm/goal).** `meta` é só o ISO de `remindAt`; tanto alarmes quanto goals (recorrentes) passam pelo mesmo `toReminderView` (persist-captures.ts:97-132 e 166-173). O `kind` do capture é `'reminder'` para ambos. Para mostrar único vs recorrente no card, é preciso estender `CaptureView` (domínio chat) + `MessagePresenter`/`AgentReplyPresenter` (`server-ben/src/presenters/message-presenter.ts`, `agent-reply-presenter.ts`) + `MessageCapture` mobile + `use-chat-messages.ts:13` / `chat-messages.ts:2-5` (tipo metadata). Só o primeiro capture da resposta vira card: `server-ben/src/routes/chat.ts:223` (`capturesResult.items[0]`) e persiste `capture: { kind, itemId }` na mensagem (chat.ts:228-229).
- Horário no card: `capture-card-meta.tsx:94-129`. `formatRemindAt(iso)`: hoje -> só relógio; amanhã -> `strings.snoozeTomorrow(clock)` ("amanhã 09:00"/"tomorrow 9:00 AM"); outro dia -> `formatShortDate, clock`. Pílula `bg-brand-50` com ícone `Clock` (linha 122-127). Só renderiza para `kind==='reminder'` e `state!=='error'`.
- Strings do card: `ben/src/pages/chat/strings/capture-card-strings.ts` (errorMessage reminder: "couldn't save this reminder — retry" / "não deu para salvar este lembrete — tentar de novo"; actionLabel só para task).
- Invalidate de cache ao criar: `pages/chat/stores/messages-store/invalidate-captured-queries.ts:7-9` (reminder -> `API_ROUTES.reminders.list`).

## 2. A "tela de lembrete" e como abrir
- É a rota `/menu` (`ben/src/core/routes.ts`: `ROUTES.menu = '/menu'`; arquivo `ben/app/(protected)/menu.tsx` -> `pages/menu/page.tsx`). Abre do chat só pelo botão do top bar: `pages/chat/page.tsx:82` `router.push(ROUTES.menu)`.
- A página Menu é uma única rota com sub-views controladas por zustand: `ben/src/layout/stores/menu-store.ts:1-42`. Estado: `view: 'menu'|'tasks'|'notes'|'reminders'`, `detailTarget: {kind:'note'|'reminder', id} | null`, `isSettingsOpen`. Ações: `selectEntry(id)` (seta `view`), `goBackToMenu`, `openDetail(target)`, `closeDetail`, `reset`.
- `pages/menu/page.tsx:15-52`: renderiza `MenuRemindersView` quando `view==='reminders'` (linha 31) e, por cima, um `SettingsSheetOverlay` que mostra `MenuSheet > ReminderDetail reminderId={detailTarget.id}` quando `detailTarget != null` (linhas 33-46). **O conceito de "lembrete selecionado" já existe = `detailTarget` (sheet de detalhe aberto).** Não há destaque/seleção na lista; "selecionado" = detalhe aberto.
- `useEffect(() => () => reset(), [reset])` (page.tsx:24) reseta o store ao DESMONTAR o Menu, não ao montar. Logo setar `view='reminders'` + `openDetail({kind:'reminder', id})` antes de `router.push(ROUTES.menu)` sobrevive (o store é global e começa no INITIAL_STATE só após fechar). Premissa a validar na implementação.
- Em hoje: quem chama `openDetail`: `menu-reminders-view.tsx:47` (`onSelect={(id)=>openDetail({kind:'reminder', id})}`) e `menu-notes-view.tsx:35`. Nenhum caminho programático de fora do menu (grep em `ben/src`): alarm popup, daily summary e notificações NÃO abrem o menu/detalhe. Toque em notificação (`services/notifications-service.ts:224-239` -> `layout/hooks/use-alarm-scheduler.ts:56-72`) só busca lembretes ativos e faz `useAlarmStore.enqueue({reminder, firedAt})` (abre alarm popup), não navega.
- `ReminderDetail` (`layout/components/menu-detail/reminder-detail.tsx:21-66`) busca o item por id sozinho (`useReminderDetailData(reminderId)`), então funciona abrindo direto pelo id mesmo com a lista fechada; trata loading/gone(404)/erro. Só mostra `ReminderEditor` se `status==='active'`.
- Header do menu: `MenuRemindersView` (`menu-reminders/menu-reminders-view.tsx:15-47`) usa `goBackToMenu` (volta para a sidebar `view='menu'`); `MenuSidebarView onClose={() => router.back()}` (page.tsx:28) volta ao chat. Se abrirmos direto em `view='reminders'`, o "voltar" do header vai à sidebar, não ao chat (comportamento a decidir).
- Rotas existentes: `ROUTES.login/chat/menu/taskWorkspace`; app files: `ben/app/(protected)/{chat,menu,tasks/[taskId]}.tsx`. Não há rota com param de lembrete.

## 3. Como a recorrência aparece hoje
Modelo (`ben/src/api/models/reminder.ts`): `ReminderKind = 'alarm'|'goal'|'conditional'`; `GoalRecurrence = {type:'none'} | {type:'daily'} | {type:'weekdays', weekdays}`; `recurrence: GoalRecurrence | null`. **Recorrência só existe para `kind==='goal'`**; `alarm` é único (persist-captures.ts cria alarm com `recurrence: null`, goal com `draft.recurrence`). Um goal com `recurrence.type==='none'` também é único (alarm-popup-overlay.tsx:71 marca done ao concluir).
- Lista (`menu-reminders/menu-reminders-list.tsx:64-77`): `MenuListRow` com `badge={<ReminderKindBadge kind/>}` (kind, não recorrência), `trailing` = `firesAtRelative(nextFireAt ?? firesAt)`, `supporting` = `strings.capturedSupporting(...)`. Badge `reminder-kind-badge.tsx:11-23` pílula `bg-surface-container-high`, label-caps mono, texto `menuStrings.reminderKinds[kind]` (`layout/strings/menu-strings.ts:33-37, 72-76`): en `Alarm` / `Goal` / `When it happens`; pt-BR `Alarme` / `Goal` / `Quando acontecer`. Headings: `activeRemindersHeading`, `doneRemindersHeading` ("Done"/"concluído"), `doneSupporting` 'done'/'concluído'.
- Detalhe (`menu-detail/item-detail-reminder-meta.tsx:17-80`): linha com tempo relativo + pílula de status (`statusActive` 'active'/'ativo', `statusDone` 'done'/'concluído') + `ReminderKindBadge`; abaixo data absoluta e `nextAlert(...)` ("next alert X"/"próximo aviso X") ou `noNextAlert` ("no upcoming alert"/"sem aviso pela frente"). **Não mostra a recorrência no meta** (só `kind`).
- Editor (`menu-detail/reminder-editor.tsx:321-340`): só para `kind==='goal'`: seção `goalTime` ("Goal time"/"Horário do goal") + `SegmentedControl` com título `recurrence` ("Repeat"/"Repetir") e opções `recurrenceNone` ("None"/"Não"), `recurrenceDaily` ("Daily"/"Diária"), `recurrenceWeekdays` ("Weekdays"/"Dias úteis") (`layout/strings/menu-detail-strings.ts:26-29, 62-65`). Alarm tem editor de horário/avisos (linha 265), sem recorrência.
- Alarm popup: `alarm-popup-alarm.tsx` usa `alarmStrings.alarmLabel` ('alarm'/'alarme') + `eventAt` ("at 9:00"/"às 9:00"); `alarm-popup-goal.tsx` usa `goalLabel` ('goal'), `goalAt`, `goalMessages`, `goalDone`; conditional usa `conditionalLabel` ('check-in') e frequências `freqDaily` ('daily'/'diária') etc. (`layout/strings/alarm-strings.ts:5-9, 19, 55-59, 69`). Nenhum mostra "recorrente" explicitamente.
- Capture card: nenhum indicador (ver item 1). Hoje é impossível distinguir único vs recorrente no chat.
- Não há string "único"/"recorrente"/"repeats"/"one-time" no mobile (grep em menu-strings, menu-detail-strings, alarm-strings): o vocabulário precisa ser criado (en + pt-BR; padrão `Localized<typeof en>` com `useStrings`).

## Dúvidas que mudam o trabalho
1. "Lembrete recorrente" no v1: a memória diz que não existe, mas o código tem `goal` com `recurrence` (daily/weekdays) e `none`. "Único vs recorrente" significa: (a) alarm = único / goal = recorrente, (b) usar `recurrence.type` (none/daily/weekdays) do goal, ou (c) distinguir alarm/goal/conditional? Define o rótulo e o que o card precisa receber do backend.
2. "Mais claro" onde exatamente: só no capture card do chat, ou também na lista de lembretes e no detalhe (hoje só há badge Alarm/Goal/When it happens)? Qual texto ("Único"/"Recorrente"? "Todo dia"/"Dias úteis"? incluir a recorrência no meta do card?).
3. "Abrir a tela de lembrete com o lembrete selecionado": é abrir `/menu` direto na view de lembretes com o sheet de detalhe daquele lembrete aberto (único conceito de seleção existente), ou também destacar a linha na lista de lembretes? E ao fechar o sheet/voltar: ir para a lista de lembretes, a sidebar do menu ou o chat?
4. Toque no card inteiro (Pressable no Root) ou um botão de ação visível como o das tasks ("Ver")? Afeta o design na galeria.
5. Vale só para o card recém-criado ou para qualquer card de lembrete no histórico (quando o lembrete foi concluído/apagado cai em `ItemDetailGone`)?

## Premissas razoáveis
- O card de lembrete inteiro vira tocável (cobre "ao clicar em um lembrete") e abre `/menu` com `view='reminders'` + `detailTarget={kind:'reminder', id: capture.itemId}` via `menu-store` (sem rota nova), reaproveitando `ReminderDetail`, que já busca por id e trata 404.
- Funciona para qualquer card de lembrete do histórico, não só o último (a mesma regra e o mesmo `itemId`).
- Único = `alarm` (e goal com `recurrence none`); recorrente = goal com `daily`/`weekdays`. O backend precisa expor isso no `CaptureView` (hoje só `meta=remindAt`); alternativa sem backend: o mobile busca o lembrete por id — mais custo, não recomendada.
- O fluxo exige desenhar primeiro na galeria (capture-reminder-* + item-detail-reminder + menu-reminders-populated, atualizando para refletir a recorrência) antes de implementar no mobile.
- Strings novas em en e pt-BR com o padrão `Localized`/`useStrings`.
