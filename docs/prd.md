# Design: Ben v1 — Voice-First Personal Assistant With Friend Tone

Generated by /office-hours on 2026-05-23

## Problem Statement

A specific busy person (the founder, dogfooding as user N=1) needs to capture notes, reminders, recurring tasks (bills due on the 15th), and one-off tasks (appointments, things to buy tomorrow) without opening three separate apps and without typing — because typing is too slow and boring for the volume of small captures a busy day produces. Today this content gets lost between a phone notes app, phone alarms, and ad-hoc chats with ChatGPT, and falls through the cracks.

Ben is a personal assistant that **behaves like a friend** — the friend-tone is the wrapper; the assistant function (capture, classify, schedule, recall) is the substance.

## Demand Evidence

- **N=1 strong signal**: The founder is the target user. They have explicitly named their own pain ("very busy days," "no time to save notes," "typing is too boring") and the workaround they want ("audio transcription").
- **Soft signal from others**: Multiple people the founder has spoken with described converging use cases — personal assistant tasks, notes, learnings, recurring reminders (e.g., "pay bills every day 15"), one-off reminders (appointments, shopping lists), trip notes.
- **Gap in the founder's data**: No one is currently paying for or using a prototype. No one has been observed using a Ben prototype unassisted. No churn data, no retention data. The founder accepted this as "no wedge validation yet" — see Premise 4.

## Status Quo

The user (and people in the founder's circle) currently solves this with **three disjoint tools**:
1. **Notes app** (phone notes / Notion) — typed, never the fastest path during a busy moment
2. **Phone alarms / reminders** — separate UI, requires intent to open
3. **ChatGPT** — for "thinking out loud," but doesn't persist, doesn't schedule, doesn't fire reminders

No single tool unifies natural-language voice capture with classification + persistence + scheduled firing + Notion sync. The pain isn't that any one tool is broken — it's that nothing is the glue.

## Target User & Narrowest Wedge

**Target user (v1)**: The founder (dom). Sample-of-one. Validation strategy is daily dogfooding. If the founder is not reaching for Ben every day within 2 weeks of v1 shipping, the wedge is wrong.

**Hypothesis for v2 expansion**: Other "busy people who hate typing" — likely operators, founders, consultants, parents juggling multiple streams. This is unvalidated.

**Narrowest wedge** (what makes Ben different from ChatGPT, Siri, Notion AI):
**Voice-first capture that classifies and acts.** Press a button, speak a sentence, Ben routes the content correctly:
- "Remind me to pay the internet bill on the 15th of every month" → recurring reminder
- "I need to buy milk, eggs, and bread tomorrow" → one-off reminder with a shopping list
- "Trip to Lisbon — book the Alfama hotel, the Cascais train, and Tasca da Esquina" → trip note
- "Sarah at Acme wants the proposal by Friday" → task + reminder

ChatGPT voice can hear this; it cannot persist it correctly or fire the reminder. Siri can sometimes fire the reminder but cannot reason about classification (note vs reminder vs trip vs task). The wedge is the **router + scheduler + memory** layered behind a voice-first interface that talks back like a friend.

## Constraints

- **N=1 user base for v1** — the founder dogfoods; no acquisition pressure yet.
- **Mobile-first** — desktop is not where busy-person voice capture happens.
- **Web v1 (alarms mocked) → React Native Expo v2 (alarms real)** — agreed phased approach. The web version explicitly cannot fully validate the "reminders fire" pillar; the founder accepted this tradeoff for iteration speed.
- **Monetization deferred** — $10/mo credit-based plan is the eventual plan, but billing infra is v1.5+, not v1. Founder is the only "customer" during dogfooding.
- **Voice/LLM costs are real** — Whisper transcription + Claude/GPT inference per voice message will be ~$0.01–0.05 each at heavy use. Credits-based pricing maps to this cost structure honestly.

## Premises

All 7 confirmed by founder:

1. **Substance = assistant; wrapper = friend tone.** Ben competes with ChatGPT + Siri + Apple Reminders + Notion AI. Not Replika.
2. **Wedge = voice-first capture for people who hate typing.** Press, speak, Ben classifies and files.
3. **Founder is the target user (N=1) for v1.** Validation = daily dogfooding. Generalization to other busy users is a v2 hypothesis.
4. **Building the full spec without validating the wedge first is a known bet.** 4-6 weeks of build before learning whether the assumption holds. Owned by founder.
5. **Mobile-first is non-negotiable.** Phone-first wedge. Web v1 is the iteration vehicle, not the long-term home.
6. **Dynamic UI "hero" components are novel but risky.** Possible with Vercel AI SDK / generative UI, but they swallow time. Stage them — they don't have to ship day-one.
7. **Credits-based pricing ($10/mo).** Maps to AI cost passthrough. Deferred to v1.5+; v1 is dogfooding only.

## Approaches Considered

### Approach A: PWA Next.js Monolith
Single Next.js 15 app, deployed as PWA. Vercel AI SDK for chat + generative UI. Supabase for Google OAuth + Postgres. Inngest for scheduled jobs. Whisper for transcription. Claude/GPT for chat. Stripe (deferred). Notion OAuth. iOS PWA push is the soft underbelly — reminders may not reliably fire on iPhone.

### Approach B: React Native (Expo) + Serverless Backend
Native iOS + Android via Expo. Native push fires 100%. Better audio UX. Same backend as A. 8-10 weeks vs 4-6 weeks. App store review gates user reach.

### Approach C: WhatsApp / Telegram Bot (Lateral)
No app. Ben lives in the user's existing chat app. Ships in 2-3 weeks but drops dynamic UI "hero," vibe selector, hamburger menu, message pinning — half the spec.

## Recommended Approach

**Phased: Approach A (web first, alarms mocked) → Approach B (React Native Expo, alarms real)** — the founder's stated path.

**Rationale**:
- Web v1 lets the founder dogfood the **chat + voice + classification + memory + Notion sync** loops in 4-6 weeks of focused build with Claude Code.
- Alarms are deliberately mocked in v1 because iOS PWA push is unreliable; this is honest scope-cutting, not failure. The "did Ben fire my bill reminder" question is answered in v2 (Expo).
- Web v1 also lets the founder share Ben via URL with the small circle of people who said it sounds useful — cheap, soft validation before native investment.
- v2 (Expo) reuses the entire backend (Supabase, Inngest, AI calls, Notion integration) and rebuilds only the UI layer with native push and audio.

**v1 spec (web, alarms mocked) — leaner than first draft to fit 4-6 weeks**:

- Google OAuth via Supabase
- Single chat page (no hamburger menu yet)
- Voice-first text input (WhatsApp-style press-and-hold) + text fallback
- **Three core action types: Note, Reminder (one-off only), Task.** Recurring reminders **deferred to v2** — there's no point storing them if nothing fires.
- **Mocked alarms = persisted with `fires_at` timestamp, surfaced as an in-app list with relative-time labels ("in 2 hours," "tomorrow 9am"). No OS notification, no web push in v1.** Web push joins in v1.x if dogfooding shows the in-app list is insufficient.
- **Memory: fixed last-20-message window, no retrieval, no dynamic switching.** Dynamic-N memory and vector retrieval are v2 — premature optimization for N=1.
- **Notion sync: deferred to v1.5.** Use an in-app notes view backed by Postgres. OAuth + page creation is ~1 week of work that doesn't change the wedge test.
- **Dynamic UI "hero" components: deferred entirely.** v1 is text + voice in, text out. The form-input "hero" is v1.x. The list-management "hero" is v2+.
- **Vibe selector: deferred.** v1 hardcodes Ben's personality via system prompt sourced from the assignment artifact ([fixtures/ben-voice.md](#the-assignment)).
- Friend tone: lives in the system prompt — slang and warmth written from day one, sourced from the fixture file.
- **Cut from v1**: Stripe payments, message pinning/reply, image attach, customer-list "hero," vibe selector UI, Notion sync, recurring reminders, dynamic UI rendering, dynamic memory window, voice replies.

**Data model (v1)**:

```
users           (id, google_sub, email, created_at)
messages        (id, user_id, role, content, audio_url?, created_at)
captures        (id, user_id, message_id, type, payload jsonb, fires_at?, status, created_at)
                — type ∈ {note, reminder, task}
                — payload examples:
                  note: { title, body }
                  reminder: { title, fires_at }
                  task: { title, done }
```

That's it. No `recurring_schedule` table, no `notion_links` table, no `vibe_settings` table in v1.

**Classification mechanism**: Claude/GPT with **tool-use (function calling)**. Define 4 typed tools — `save_note`, `save_reminder`, `save_task`, `ask_clarifying_question`. The model picks the right tool per turn. No router-prompt-then-parse string-matching. Tool schemas double as the validation layer.

**Transcription budget**: ≤30-second voice clips, webm/opus encoding (Whisper's preferred), target <3s end-to-end (record stop → text reply visible).

**Week-1 spike (gates the whole project)**: Prove iOS Safari MediaRecorder works for press-and-hold audio capture with acceptable quality and that the recorded blob successfully transcribes via Whisper. iOS Safari has known quirks (no `audio/webm` support natively, needs `audio/mp4` fallback). **If this spike fails, the wedge cannot ship on iOS web — pivot to Telegram bot (Approach C) for validation before committing to web.**

**v1.5 (web, dogfooding-driven additions, only if v1 wedge holds)**:
- Notion OAuth + write-only sync (Ben creates/updates pages he made)
- Web push (best-effort, knowing iOS PWA push is flaky)
- Form-input "hero" (the one-pattern generative UI for context gathering)
- Stripe + credits if anyone besides the founder wants to use it

**v2 (React Native Expo, real alarms)**:
- Native push notifications — wire up Inngest or BullMQ scheduler at this point (premature for v1's mocked alarms)
- Recurring reminders — only now do these make sense, since they actually fire
- Native audio capture with WhatsApp-style gestures
- Two-way Notion sync (read + write)
- Vector retrieval over older notes for long-tail memory
- Vibe selector (if dogfooding revealed alternative tones worth A/B testing)
- App store submission
- List-management "hero" components

## Open Questions

1. **What does "Ben's voice" actually sound like?** Resolved by the Assignment: 10 example exchanges in [fixtures/ben-voice.md](#the-assignment). This file is a v1 blocker — Ben's system prompt is generated from it.
2. **Does iOS Safari MediaRecorder work for press-and-hold capture?** Open until the week-1 spike runs. If it fails, the v1 plan pivots — see "Week-1 spike" in the v1 spec.
3. **Voice output**: text-only replies for v1, or does Ben speak back (ElevenLabs / OpenAI TTS)? Voice replies double cost per message and most "busy person" moments don't have headphones in. **v1: text-only replies confirmed.** TTS is v1.5+.
4. **What signal flips Ben into "ask a clarifying question" mode** vs. just classifying-and-filing? Current plan: the `ask_clarifying_question` tool is one of the four tools the model can pick — Ben decides on its own based on the system prompt. Tune via the fixture file.

## Success Criteria

**v1 success (the only one that matters)**:
- Founder uses Ben for ≥1 voice capture per weekday for 2 consecutive weeks within 30 days of v1 shipping.
- Founder can articulate one specific thing Ben did *better than the status quo* (faster, more reliable, more satisfying) without prompting.
- The classification router gets the right tool ≥85% of the time on the 10-exchange fixture file (and any new exchanges added during dogfooding).

**v1 failure modes (be honest about these)**:
- Founder stops opening Ben after week 2 → wedge is wrong; voice capture isn't actually the bottleneck.
- Founder uses Ben for chat but never captures notes/reminders → product collapses into "another ChatGPT skin."
- Notion sync goes unused → either the integration is wrong or the founder doesn't actually live in Notion.

## Distribution Plan

- **v1**: Vercel deploy of the Next.js PWA. Founder shares URL directly with the soft-validation circle. No app store, no paid ads, no signup wall beyond Google OAuth.
- **v2**: Expo EAS Build → TestFlight + Google Play internal testing → public store submission once the loop is validated. No marketing site / waitlist until v2 unless v1 dogfooding signal is strong enough to seed organic interest.

## Dependencies

**v1 (minimal)**:
- Anthropic or OpenAI API key (chat + tool-use classification)
- OpenAI API key (Whisper transcription) — Anthropic doesn't currently offer transcription
- Supabase project (Google OAuth + Postgres) — free tier sufficient for N=1
- Vercel deployment
- **No Inngest in v1** — mocked alarms means no scheduler needed. Add in v1.5/v2.
- **No Notion integration in v1** — deferred to v1.5.

**No external blockers**. All v1 dependencies have free tiers or pay-as-you-go pricing.

## The Assignment

**Before writing a single line of code, do this:**

Create `fixtures/ben-voice.md` and write **10 example exchanges with Ben**. The user voice-captures something, Ben responds. Cover the four main routing cases:
- Note (something to remember, no scheduled action)
- One-off reminder (with a `fires_at`)
- Task (something to do, no time)
- Clarifying question (ambiguous input where Ben asks back)

Plus 6 more across the same four categories, mixing in some real-life capture you've actually had today.

Write Ben's responses in the *exact tone you want* — slang and all. This file:
1. **Becomes the system prompt foundation** (you'll paste it directly into the Claude/GPT instructions).
2. **Doubles as the v1 eval set** — the 85% classification success metric is measured against this file.
3. **Becomes the v1 blocker** — if you can't write 10 good Ben exchanges in your own voice in 30 minutes, the friend-tone wrapper isn't yet a real product decision. Find that out now, not after 6 weeks of building.

Then, **week 1, before any UI work**: run the iOS Safari MediaRecorder spike. Record audio in mobile Safari, upload to Whisper, get text back. If it works at acceptable quality and latency, v1 proceeds. If it doesn't, see the pivot note in the v1 spec.

## Reviewer Concerns

This doc went through one round of adversarial review (cold subagent, no session context). Initial score 6/10 — overscoped for the 4-6 week timeline. Fixes applied: Notion deferred to v1.5, recurring reminders deferred to v2, dynamic UI "hero" deferred entirely, Inngest dropped from v1, memory locked to fixed 20-message window, data model added, classification mechanism specified (tool-use with 4 typed tools), iOS Safari MediaRecorder spike added as week-1 gate, mocked alarms definition tightened, contradictory web-push success criterion replaced with classification-accuracy metric.

**Unresolved**: The 4-6 week timeline is still aggressive even after cuts. Realistic outcome is closer to 5-7 weeks at solo-with-Claude-Code pace. Calibrate expectations.
